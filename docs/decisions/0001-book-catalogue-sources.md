# ADR 0001: Book catalogue sources

- Status: Proposed - awaiting decision by Matúš
- Issue: LIB-7 (spike), feeds LIB-25 (bulk import + ISBN lookup)
- Date: 2026-10-28 (all sources and lookups below checked on this date)

## Context

Search (`GET /v1/books`) is only as good as the catalogue behind it. Libro Club readers are Slovak, read Slovak originals, Slovak and Czech translations and English books; Ukrainian comes later. The `books` module already models works, authors (`work_authors` with position) and editions (`isbn13` unique and nullable, `language` ISO 639-1, `title`, `published_year`). `POST /v1/books` lets any authenticated user add a published book today, with no moderation and no record of where data came from.

We need: a bulk seed with good Slovak / Czech coverage, an on-demand lookup by ISBN, a flow for books nobody has, and covers we are allowed to show. Licences must allow storing the data in our own database for a product that may charge users later (Stripe is planned).

## Recommendation

Combine sources in this order; every source sits behind one adapter interface (`CatalogueSource`) so LIB-25 can add or drop sources without touching the core.

1. **Bulk seed from NKP (CC0).** Import CNB and SKC MARC21, filtered to language `slo` / `cze` (MARC 008/35-37 and 041) and to records with an ISBN (020 $a), plus authorities for author identity. Weekly files allow a periodic, idempotent re-import. This is the biggest legal SK/CZ source today.
2. **Bulk seed from the Open Library dump (CC0).** Editions in `slo`, `cze` (and `ukr` when Ukrainian starts) in full; English filtered (ISBN present, plus popularity from the reading-log / ratings dumps or a work count cap) so the database does not grow by tens of millions of rows. OL supplies work grouping and cover ids.
3. **On-demand ISBN lookup** when a search or an ISBN scan misses: our DB, then the Open Library `/isbn/{isbn}` API (identified `User-Agent`, at most 1-3 req/s, result stored with provenance, never proxied as live search), then NKP Z39.50, then SNK Z39.50 only once SNK allows it. Results are cached as catalogue rows, which CC0 allows.
4. **User submission with moderation** for whatever is still missing (see below).
5. **Ask SNK** (helpdesk@snk.sk, isbn@snk.sk) for permission to use the Slovak national bibliography as a dump or via OAI-PMH / Z39.50, ideally under CC0 like NKP, and for the ISBN agency's list of reported (forthcoming) books. A yes makes SNK source 1; this is the single biggest win for Slovak coverage.
6. **Wikidata (optional enrichment):** QIDs linking works and authors across OL and NKP ids, original titles for translations.

## Data model notes

- **Work vs edition:** MARC has no work record. Group editions into works by OL work key, then MARC 240 / 765 (uniform title, original-language entry, e.g. Slovak "Premena" under Kafka's "Die Verwandlung"), then Wikidata; otherwise one work per edition and merge later in moderation. Edition `title` keeps the translated title, as today.
- **ISBN:** normalise to ISBN-13 on import (`domain/isbn10.ts` already converts); MARC 020 often carries qualifiers ("(viaz.)") and invalid ones in 020 $z, which are dropped. Slovak publishers have reused or mistyped ISBNs, so a clash on `editions_isbn13_key` with different metadata goes to moderation instead of overwriting.
- **Editions without ISBN** (older books) stay allowed; they deduplicate by source id only.
- **External ids per source:** new tables, e.g. `books.edition_sources (edition_id, source, external_id, fetched_at, licence)` with `edition_sources_source_external_id_key`, and the same for works (OL work key, Wikidata QID) and authors (OL author key, NKP authority id, Wikidata QID). Source values: `open_library`, `nkp_cnb`, `nkp_skc`, `snk`, `wikidata`, `user`. This makes re-imports idempotent and lets us delete or re-attribute data per source.
- **Author identity:** never merge by name alone (OL alone has three records for Dominik Dán). Prefer NKP authority ids and Wikidata, then OL keys; merges are explicit and recorded. Import only the name and ids, not the personal data in authority records (birth data, notes), to stay within GDPR minimisation.
- **Language codes:** sources use MARC / ISO 639-2 (`slo`, `cze`, `ukr`, `eng`); map to ISO 639-1 (`sk`, `cs`, `uk`, `en`). The current `editions_language_check` (`^[a-z]{2}$`) cannot store unknown or multiple languages (`und`, `mul`) or languages without a 639-1 code; decide between a nullable language or allowing 639-2/3 codes.
- **Provenance and attribution:** CC0 requires nothing, but NKP and OL ask for a courtesy mention; one "Data sources" screen (NKP, Open Library, Wikidata) covers both. Keep `fetched_at` so stale on-demand rows can be refreshed.
- **Status:** works and editions need a `status` (`published`, `pending`, `rejected`) and `submitted_by` for user submissions; search shows `published` plus the user's own `pending` books.

## Covers

- **Open Library covers** by cover id (from the dump, `covers.openlibrary.org/b/id/{id}-M.jpg`): id lookups are not rate limited like ISBN lookups, display by linking is what OL intends, a courtesy link back is "appreciated". No explicit caching rule; honour HTTP cache headers and do not mirror the archive.org cover dumps in bulk. Coverage for Slovak books is low (2 of 8 Dán works).
- **Copyright:** cover artwork belongs to publishers (Databáze knih says so explicitly). OL and Google do not license covers to us; storing copies is reproduction, so permanent storage needs the publisher's consent. Google Books thumbnails may not be stored and require Google branding; obalkyknih.cz may not be stored and is library-only.
- **Publisher covers (main path for SK):** ask the big Slovak publishers (Slovart, Ikar, Albatros Media SK, Artforum / Absynt and others) for permission to store and show covers, or for a feed; publishers already give covers to Martinus and obalkyknih for promotion, so a written yes is realistic. Store them in our object storage through the `media` module.
- **User photos of their own copy:** allowed through `media` (EXIF / GPS stripped) and moderation, with terms where the user grants us a licence for the photo; whether a photo of a cover is fine for identification is an open legal question.
- **Fallback:** a generated typographic cover (title + author, deterministic colours) so the app never shows an empty box.

## Missing books flow

1. Search finds nothing: the app offers "Scan or type the ISBN".
2. With an ISBN, the backend runs the on-demand lookup (Recommendation 3). A hit creates the edition (and work / authors if new) as `published` with provenance and returns it.
3. No hit or no ISBN: the user fills a short form (title, authors, language, year, optional ISBN, optional cover photo). The book is created as `pending`, owned by the submitter, usable immediately (they can start a reading session), invisible to others.
4. Before saving, the backend suggests likely duplicates (normalised title + author search, ISBN) so the user can pick an existing book instead.
5. A moderation queue (Libro Club moderators / admin) approves, edits, merges into an existing work or rejects. Merging publishes a domain event, e.g. `WorksMerged` v1 (`{ fromWorkId, toWorkId }`), because `reading-sessions` stores `work_id` without an FK and has to re-point readings; `BOOK_CATALOGUE.workExists` must accept the submitter's own pending works.
6. Abuse limits: rate limit submissions per user, and replace today's unmoderated `POST /v1/books` with this flow (or restrict it to moderators).

## Risks and open questions

- **SNK permission** is unknown; without it Slovak coverage relies on NKP SKC, OL and users. Contact is a non-dev task (who writes to SNK?).
- **Monetisation:** any paid plan rules out Google Books for good; confirm we never want it.
- **English scope:** how much English to import up front vs on demand (DB size, search quality); ISBNdb if the gap is real.
- **Data quality:** MARC records from many libraries duplicate the same edition, carry braille / audio / item records, and have inconsistent author forms; the import needs filters (format, 020 present) and dedupe by ISBN-13.
- **Personal data** flags on NKP datasets: import only bibliographic fields and author names.
- **Covers law:** storing publisher covers without consent is a copyright risk; get consent first, link-only until then.
- **OL fair use:** OL may block heavy use; the API stays a low-volume fallback with caching.
- **Moderation load:** who moderates and how fast; pending books must work for their owner meanwhile.
